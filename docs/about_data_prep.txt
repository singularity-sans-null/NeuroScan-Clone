why we chose a batch size of 32: 
A batch size of 32 provides a good balance between computational efficiency and learning stability. 
A batch size of 1 results in noisy weight updates because each update is based on a single image. 
On the other hand, using all training images at once requires excessive GPU memory and produces 
fewer weight updates per epoch. A batch size of 32 allows efficient GPU utilization while providing 
stable gradient estimates.
